# Completeness derivation — SC 4.1.2 Name, Role, Value, clearing direction

**Resolver:** `all-true-completeness-v1` · **Clearability:** `closed-scope-clearable` (closed state set) ·
**accessibilitySupportDependent:** `true` (the AX exposure IS the AT-facing surface) ·
**Experiment:** `ax-state-diff` (CDP `Accessibility.getPartialAXTree`).

SC 4.1.2 (A): name, role, and states/values are programmatically determinable and changes are
notified to AT. "All states" is finite **per ARIA role** (a checkbox has `checked`; a disclosure has
`expanded`; a tab has `selected`) — that is the soundness foothold. It becomes **open** when a widget
carries app-specific states with no ARIA mapping, or state lives only in a CSS class. This clear is
scoped to **name + role + a single closed ARIA state**; live-region NOTIFICATIONS are out of scope.

| Obligation (typed-outcome flag) | Why necessary |
|---|---|
| `hydrationReady`, `axNodeResolved` | the element must map to a non-ignored AX node on a hydrated page (a pruned/`aria-hidden` node ⇒ INCONCLUSIVE, never a barrier). |
| `axRolePresentAndExpected`, `axNamePresent`, `axNameNotFromError` | a determinable, non-error accessible name and a real role. |
| `axStatePropertyExposed` | the relevant ARIA state exists as an AX property pre-activation. |
| `axStateChanged` + `axDomAgree` | the state changed in a FRESH AX snapshot AND it agrees with the independent DOM channel (never echo DOM for both — that is the channel that catches "DOM flipped, AX didn't"). |
| `axDiffStable` | the post-activation AX state reproduced on a re-read (no stale/race read). |
| `activationWasReal`, `noNavigation` | a real activation, and the page did not navigate away (else the AX tree is a different document). |
| `statesInventoryClosed` | **universe-closing obligation.** The element carries exactly one settable ARIA state (or its role prescribes one); an open/custom-state widget fails this and auto-PARTIALs. |

A widget whose DOM state changed but the AX tree did not reflect it, or one with no accessible name,
is a sound `BARRIER_OBSERVED`. Because the clear is AT-dependent and baseline-relative (CDP/Chrome AX
computation), the builder additionally requires a declared AT baseline (Rule 12).

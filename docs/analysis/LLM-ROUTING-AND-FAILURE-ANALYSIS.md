## Executive Summary

The harness routes an obligation to the LLM only when `familiesFor()` (scripts/v3/lib/applicability-oracle.js:110) enumerates it from a *static element fact* and it lands auto-PARTIAL. That gate is the right idea — route the deterministically-unsettleable residue to human-like judgment — but it is keyed on a **frozen, role-name-shaped element type**, while the judgment-worthy facts are overwhelmingly **state transitions, inter-element relationships, and perceptual/semantic adequacy calls** the single-shot bundle cannot carry. Three structural failure modes recur across both analyses. First, **whole classes of elements are invisible to the LLM** because either the collector drops them (no widget role / no text / not focusable / not an image → never recorded) or the gates fire on a *closed* set of leaf-widget role strings, so every composite/container role (menu, tree, grid, tablist, dialog) and every dynamic situation (4.1.3 status, 1.3.2 sequence, 2.2.2 motion, disclosure reveal) enumerates *nothing*. Second, **already-computed facts dead-end**: `roleOverridesNative`, `mediaErrorName`, `placeholder`, the `states`/`axStates` bundle, `needsPixelContrast`, `hasHoverContent`/`underOverlay` (hardcoded `false`), and the entire axe checker lane are collected/computed but consumed by no family or rubric. Third, **the boundary leaks both ways** — deterministically-settled facets (name presence, exact contrast ratio, ARIA validity, target-size px) reach the LLM and cost spend or *false-clear*, while a genuine human-judgment facet (named-iframe equivalence) under-routes because a collected fact is empty.

The failure analysis (results/fn-llm) makes the second takeaway concrete and reassuring: **the LLM is mostly not wrong — the harness mostly never gives it a fair shot.** Of the diagnosed FN/UNCERTAIN/NOVERDICT cases, the dominant root cause is *missing or mis-provisioned evidence*, not bad model judgment. All three NOVERDICT cases trace to one bug — `document.evaluate(xpath,…,9,…)` in vision-capture.js cannot resolve SVG-namespaced nodes, so every SVG graphic/link silently loses its crop and abstains at the required-evidence gate (llm-adjudicator.js:438). Both 1.4.3 false-clears trace to vision being handed a measurement it structurally cannot make, while `needsPixelContrast=true` (eval-page.js:480) — the flag built to route exactly that case to a pixel runner — dead-ends into the LLM lane because no pixel runner consumes it. The UNCERTAIN cases are page-level rubrics built from an *empty stub* because synthetic xpaths have no element and `precomputeSignals` has no page-level branch. The governing fix-principle for both analyses is identical and should be stated as policy: **route by the FACET, not the SC.** Presence, geometry, contrast-ratio-over-flat-color, and ARIA/attribute validity are deterministic and must be *owned by a checker/runner and subtracted from auto-PARTIAL before LLM selection*; only meaning, adequacy, descriptiveness, equivalence, appropriateness, and readability-over-non-flat-backdrops are LLM-appropriate.

## Analysis 1 — Beyond `noObligation`: what else should reach the LLM

The governing principle, stated up front: **route by the FACET, not the SC.** A single SC has both deterministic and human-judgment facets — 1.1.1 *presence* (axe `image-alt`) is deterministic, 1.1.1 *name-vs-pixel adequacy* is LLM; 1.4.3 *flat-color ratio* is deterministic, 1.4.3 *readability over a photo/gradient* is LLM; 4.1.2 *name presence* and *ARIA validity* are deterministic, 4.1.2 *composite name/state coherence* and *named-iframe equivalence* are LLM. The oracle gates today key on the SC-bearing element type; they should key on the facet.

### 1A. Element types / tags

Two structural facts make whole classes of elements invisible. (1) The collector universe is widget-centric: the synthetic ACT collector keeps a node only if `focusable || isFormField || sampledRole || text || isImage` (act-page-collect.js:137), and the real collector only records sampler-picked nodes — so a role-stripped `<svg>`/`<canvas>`, a media container, or a custom element is dropped before `familiesFor` sees it. (2) The gates fire on a closed role set: `WIDGET_ROLE`/`FORMFIELD_ROLE` match only *leaf* widgets, so every composite/container role enumerates no name-role-value and no label obligation — exactly where name/role/state correctness is hardest and a checker abstains.

### NOVERDICT — one bug, three cases (HARNESS)

All three: the SC-relevant subject IS enumerated and IS handed to `runRubricJudgments`, but abstains at the required-evidence gate (llm-adjudicator.js:438) because both declared vision frames are missing — returning `null` *before* `runAgent`, leaving no trace and no verdict. The frames are missing not because the element is hidden (boxes are 1264×1264 / 78.8×78.8, fully visible) but because vision-capture.js resolves the xpath with `document.evaluate(xpath, document, null, 9, null)`, whose **unprefixed name-test matches only NULL-namespace HTML nodes** and returns `singleNodeValue=null` for SVG-namespaced nodes. The collector emits namespace-agnostic lowercase-tag xpaths, so every SVG graphic/link silently gets no rect → no crop → abstain. Both competing hypotheses are disproven: "0×0/not-collected" (FALSE — boxes large) and "fd3a94 SC-facet mismatch" (FALSE — single-link `link-purpose-v0` caught the sibling HTML variants).

### UNCERTAIN — page-level rubrics built from an empty stub (HARNESS)

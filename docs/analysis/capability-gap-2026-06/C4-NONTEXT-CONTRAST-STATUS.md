# C4 — Non-text contrast runner (1.4.11): status

**What it is.** `scripts/v3/lib/nontext-contrast-runner.js` — the deterministic 1.4.11 producer the
`non-text-contrast-v0` rubric was already written against (the rubric says "the deterministic runner already
CLEARS/fails every component it can reduce to two flat colors" — that runner did not exist until now).

**Model.** A component is perceivable iff the STRONGEST distinguishing cue (an opaque border side, the opaque
fill when ≠ adjacent, or — under focus — the outline) has ≥ 3:1 vs the ADJACENT surface. Decide only when flat +
opaque; abstain on gradient/photo/semi-transparent/graphical/occluded (defer to the rubric). Exemptions:
disabled/inactive, default-UA (native + no author appearance — detected via inline style + author CSS rules,
NOT computed presence), aria-hidden.

**Validation (independent corpus, 164 cases / 7 aspects, generated by 3 separate agents — held-out set untouched):**
- Self-test: 12/12 on hand-built deterministic cases.
- Corpus iteration log: 18/116 (selector bug) → 60% (subject discovery) → graphical-abstain (10 false-barriers→0)
  → focus-occlusion-abstain (false-clears 13→9). Current: **coverage 105/164 decided; DANGEROUS = 9 FC / 11 FB / 4 FE.**
- SOUND on its core: adjacent-color, exemption, boundary component cases; correctly abstains on graphical +
  occluded-focus (safe deferral to the rubric).

**Remaining dangerous errors → ROOT CAUSE = geometric adjacent-surface resolution (the next iteration):**
- state-indicator FB5, boundary FC2/FB3, adjacent-color FB2: the "adjacent color" for 1.4.11 is the actual
  rendered pixels NEXT TO each boundary side (a toggle knob vs its track; a button border straddling two
  surfaces — worst-SIDE governs), NOT a single walked-up ancestor background. Fix: render the component region +
  sample the adjacent pixels per side (+ the inside fill), worst-side governs — the same pattern as
  `text-contrast-pixel`'s backdrop percentile sampling, applied to the component perimeter.
- focus-geometry FC3: partial-perimeter / off-component indicators pass on color but fail on geometry — needs the
  same per-side pixel sampling to see which perimeter portion is actually contrasting.
- A few FE (false-exempt): exemption-trap labeling edge (aria-disabled-but-operable) — a philosophy call, low priority.

**Next steps:** (1) pixel per-side adjacent sampling (fixes the FB/FC cluster); (2) re-validate to ~0 dangerous;
(3) wire into the oracle's `non-text-contrast` family + build-v3 as a deterministic disposition feeding the rubric
the `contrast.uncertainReason` on abstain. THEN proceed to the next capability.

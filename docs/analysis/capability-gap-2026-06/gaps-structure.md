# Capability-gap analysis — STRUCTURE SCs (1.3.1, 1.3.2, 2.4.10, 2.4.6, 2.4.2)

35 aspects. Coverage judged against the *current* code (not the stale inventory note). Two collectors the
harness-capability-inventory marks "NO" actually EXIST now and change several verdicts:
- `scripts/v3/lib/collect-tables.js` — per-`<table>` relationship facts (caption, th/scope, `headers=` IDREF
  resolution + `danglingIdref`, `headerWithNoDataCell`, `looksLikeDataTable`) → threaded as `structure.tables`.
- `scripts/v3/lib/collect-lists.js` — real `ul/ol/dl` semantics + *faux* candidates (br-bulleted / sibling-bulleted
  via a leading-marker regex) → threaded as `structure.lists`.
- Heading tree (`act-page-collect.js` :609) carries CDP-corrected accessible `name`, `level`, `ariaHidden`,
  `offscreen`; `capture_full_page` (cdp-tools.js :869, LLM-callable) returns off-viewport heading geometry
  (`offDocument`/`verticalPositionPct`/`inViewport`).

The PERSISTENT structural limits that drive the GAP/PARTIAL verdicts below:
- **Rubric VISION evidence is `viewport`-only** for 1.3.1/1.3.2/2.4.6/2.4.10 → the vision channel is blind below
  the fold / off-screen. (Structured signals see the whole DOM; `capture_full_page` exists but is LLM-triggered,
  not guaranteed, and returns pixels the *viewport-declared* rubric isn't reliably prompted to fetch.)
- **No DOM-vs-visual reading-order signal beyond the column-aware within-column VSR detector** (`order-check.js`):
  it deliberately never flags CROSS-column moves (RTL / linearized-table / masonry / Z-order), so those 1.3.2
  facets are mechanically un-enumerated.
- **No CSS-render-vs-source-order signal** (flex/grid `order`, `direction:rtl`, absolute positioning) other than
  the VSR geometric rank, and **no responsive/breakpoint re-capture**.
- Faux-list / faux-table detection is **marker-regex heuristic** (bullets/numbers, `<br>`/sibling blocks); it does
  NOT detect ASCII/`<pre>` whitespace-aligned columns or whitespace-within-word artifacts.

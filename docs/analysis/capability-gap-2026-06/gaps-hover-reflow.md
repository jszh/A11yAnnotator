# Capability-gap analysis — 1.4.13 (Content on Hover or Focus) & 1.4.10 (Reflow)

Reasoned from aspect slug names + WCAG 2.2 Understanding/Techniques + Trusted Tester v5.1.3 + EN 301 549, against the
v3 harness's CURRENT capability (hover-content-tri runner + hover-content-v0 rubric; reflow-overflow-probe + reflow-no-hscroll-v0
rubric; measure_geometry_live / set_state_and_capture CDP tools). HARD CONSTRAINT honored: no held-out case content read.

Adversarial stance: a runner existing ≠ aspect covered. The hover-content-tri runner drives the POINTER only
(`page.mouse.move`) — it never focuses the trigger, and its Esc-dismiss test presses Escape with the pointer parked
on the trigger, NOT with keyboard focus on it. The reflow probe measures one width (320×256) and applies a TABLE/MAP/SVG
exemption heuristic; it does not detect F102 disappearance, C33 unbreakable strings as a distinct class, or G224/G225.

It also does not verify the dismiss left the hover/focus undisturbed. And `dismissExempt = tip && !obscures` short-circuits the whole test when the tooltip overlaps no text-bearing element, which UNDER-tests overlays that obscure non-text content (icons, controls). Needs: Esc-dismiss probe in BOTH hover-held and focus-held states that asserts trigger hover/focus is unchanged after Esc. | esc-dismiss-focus-held-probe |

| 1.4.13 | hover-content-no-keyboard-focus-trigger-path | Applicability/parity: content shown on HOVER must (per the SC's pointer/keyboard parity) also be available on keyboard FOCUS; a hover-only reveal with no focus-trigger path is a barrier. | Focus the trigger via keyboard and confirm the SAME additional content is revealed (focus-reveal parity). | GAP | Runner NEVER focuses the trigger — it does a STATIC focusability check (`tabIndex`/tag) and explicitly comments "never call el.focus() here" to keep the rest baseline pristine. It detects content only via `page.mouse.move`. So a hover-only reveal with no focus path is invisible to the runner and the rubric (its state-after is a HOVER capture, not a focus capture). Needs: a focus-reveal capture (focus the trigger, re-run docSig) to test hover↔focus parity. | focus-reveal-capture |
| 1.4.10 | non-excepted-horizontal-overflow-at-320px | Core: at 320 CSS px width, non-excepted content must reflow without requiring horizontal scroll in a second dimension. | Load at 320×256, detect horizontal scroll + locate the on-screen overflow source, exclude excepted content. | COVERED | reflow-overflow-probe sets 320×256, hydrates, settles, re-measures for stability (`reflowSettled`), and reports `overflowBarrierObserved` only for a non-exempt on-screen overflow source crossing the right edge; rubric judges the residual ambiguous cases. Barrier-only by design (a conservative exemption can only suppress a barrier, never manufacture a clear). | reflow-320-overflow-probe |
| 1.4.10 | f102-content-disappears-no-equivalent | F102: content that DISAPPEARS at 320px (clipped/hidden by the reflow) with no equivalent provided is a failure, not a pass. | Diff content present at wide width vs present at 320px and flag content that vanished with no equivalent. | GAP | The probe measures overflow/clipping at 320px ONLY; it never captures a wide-viewport baseline to DIFF against, so content that simply disappears at 320px (display:none breakpoint, clipped-and-lost) produces NO overflow source and reads as "clean reflow" — a false negative. `clipHidingDetected` catches overflow-x:hidden with wider scrollWidth, but NOT content removed entirely. Needs: wide-vs-320 content diff (enumerate text/controls present at desktop width but absent/clipped at 320px with no equivalent — F102). | reflow-content-disappearance-diff |
| 1.4.10 | long-unbreakable-string-overflow-c33 | C33/C31: a long unbreakable string (URL, code token) may overflow at 320px; whether it is a genuine barrier depends on whether wrapping/breaking is available (C33) vs an unavoidable token. | Identify the overflow culprit as a long unbreakable string and judge whether breaking is owed (C33) or excepted. | PARTIAL | The probe locates an overflow source crossing the right edge but does NOT classify it as a long-unbreakable-string token, nor check `overflow-wrap`/`word-break` CSS to see if breaking is available (C33). It would report such a string as a generic barrier; the rubric is told to exempt "code" but has no signal that the overflow IS an unbreakable string vs a wide text block. Needs: culprit classification = single unbreakable token + CSS break-availability signal (overflow-wrap/word-break/hyphens). | unbreakable-string-classify-c33 |
| 1.4.10 | two-d-exception-overclaimed-or-misscoped | The "requires 2-D layout for usage/meaning" exception (tables, maps, diagrams, code) must apply ONLY to the intrinsic content, not the page chrome around it; over-claiming it is a failure. | Classify the overflow source's 2-D-necessity AND scope the exemption to the content, not surrounding chrome. | PARTIAL | Runner's `isExempt` walks ancestors for MAP/SVG/role=table|grid|treegrid, or TABLE with th/caption, or any ancestor with overflowX:auto/scroll. This OVER-applies: any ancestor scroll-container exempts the child (chrome counted as 2-D content), and th/caption is a SIGNAL not proof of 2-D-necessity (the code itself notes this is "not proof"). It sets `dataTableExemptionApplied` so a suppressed barrier is surfaced, but the rubric must re-adjudicate from the crop alone — and it isn't told WHICH element was exempted or WHY. Needs: pass the exempted element's identity/role + the 2-D-necessity rationale to the rubric, and tighten the ancestor-scroll-container over-exemption. | two-d-exemption-scoping |
| 1.4.10 | sticky-fixed-content-consumes-small-viewport | Sticky/fixed content (headers, sidebars, cookie bars) that consumes a large fraction of the 320px viewport, leaving too little for content, is a reflow barrier. | Measure sticky/fixed-positioned regions' viewport coverage at 320px and flag excessive consumption. | GAP | The probe's overflow test is about HORIZONTAL scroll; it has no notion of position:sticky/fixed elements consuming the small viewport. A fixed sidebar that does not itself overflow horizontally but squeezes content produces no `overflowBarrierObserved`. measure_geometry_live gives boxes but isn't wired to enumerate fixed/sticky coverage. Needs: detect position:fixed/sticky elements + compute fraction of the 320×256 viewport they occupy. | sticky-fixed-viewport-coverage |
| 1.4.10 | carousel-panel-overflow-g225 | G225 / panel overflow: a carousel or paged panel that overflows horizontally at 320px and cannot be reached without horizontal scroll (vs a legit author-provided horizontal-scroll affordance). | Detect a multi-panel/carousel horizontal-overflow region and judge whether panels are reachable without 2-D scroll. | GAP | The probe treats ANY ancestor with overflowX:auto/scroll as exempt ("author-provided 2D affordance"), which would EXEMPT a broken carousel track that requires horizontal scroll to reach panels — the opposite of G225's intent. It has no carousel/panel-group recognition and cannot tell a reachable-via-controls carousel from one that strands panels off-screen. Needs: carousel/paged-panel detection + reachability check (are off-screen panels reachable by non-scroll controls?). | carousel-panel-reachability-g225 |
| 1.4.10 | meaningful-indentation-vs-gratuitous-g224 | G224 / preserving meaning: distinguishing indentation/whitespace that carries MEANING (must be preserved on reflow) from gratuitous indentation that may collapse — at 320px structure should not be destroyed. | Judge whether reflow at 320px collapsed meaningful indentation/structure vs harmless gratuitous whitespace. | GAP | Purely a semantic-meaning judgment about whether collapsed indentation carried meaning; the probe measures overflow only and emits no indentation/whitespace-structure signal. The rubric's declared evidence is the 320px crop alone — it cannot compare the wide-width structure to the 320px structure to see if meaningful indentation was lost. Needs: a structure/indentation comparison (wide vs 320) + a meaningful-vs-gratuitous signal; this is the high-PARTIAL aspect (2F/4P) — largely a judgment gap, not just an evidence one. | indentation-meaning-preservation-g224 |

## Capability tags (clustered)

**1.4.13 hover/focus property-driving (6 aspects → 6 tags):**
- `hover-pointer-travel-walk` (1 aspect) — walk the actual trigger→content gap corridor (gapX/gapY) to catch F95 dead-zones, not a straight midpoint hop.
- `ua-title-exemption-classify` (1 aspect) — COVERED; native `title`/UA-tooltip exemption already handled by `hasNativeTitleOnly`.
- `esc-dismiss-focus-held-probe` (1 aspect) — Esc-dismiss in BOTH hover-held and focus-held states, asserting hover/focus undisturbed.
- `occlusion-meaningful-vs-decorative` (1 aspect) — surface occludedElements[] (role/interactivity) into the rubric to judge meaningful-vs-decorative obscuring.
- `hover-persistence-timing` (1 aspect) — parameterized persistence-timer probe distinguishing forbidden auto-timeout from valid invalidation (current dwell is a fixed ~1.6s).
- `focus-reveal-capture` (1 aspect) — focus the trigger and capture the focus-reveal to test hover↔focus parity (currently NEVER focused).

**1.4.10 reflow exception detection (7 aspects → 7 tags):**
- `reflow-320-overflow-probe` (1 aspect) — COVERED; core 320×256 non-excepted-overflow detection.
- `reflow-content-disappearance-diff` (1 aspect) — wide-vs-320 content diff for F102 content that vanishes with no equivalent.
- `unbreakable-string-classify-c33` (1 aspect) — classify overflow culprit as an unbreakable token + CSS break-availability (C33).
- `two-d-exemption-scoping` (1 aspect) — pass the exempted element identity/2-D-rationale to the rubric; tighten over-broad ancestor-scroll-container exemption.
- `sticky-fixed-viewport-coverage` (1 aspect) — detect position:fixed/sticky elements consuming the 320×256 viewport.
- `carousel-panel-reachability-g225` (1 aspect) — carousel/paged-panel detection + off-screen-panel reachability (current code wrongly exempts any overflowX:auto ancestor).
- `indentation-meaning-preservation-g224` (1 aspect) — wide-vs-320 structure/indentation comparison + meaningful-vs-gratuitous judgment.

**Cross-SC reusable patterns:**
- `focus-reveal-capture` overlaps with the documented reveal-state-discovery gap (no reveal-state producer) — the harness has no focus/disclosure-reveal capture lane.
- `reflow-content-disappearance-diff` and `indentation-meaning-preservation-g224` both need a WIDE-vs-320 baseline diff — a single shared "two-width content/structure diff" capability would serve both.
- `two-d-exemption-scoping`, `unbreakable-string-classify-c33`, `carousel-panel-reachability-g225` all need richer OVERFLOW-CULPRIT CLASSIFICATION beyond the current "crosses-right-edge + ancestor-tag exemption" — a shared culprit-classifier (token vs table vs map vs carousel vs chrome) would serve all three.

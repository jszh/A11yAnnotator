# Capability-gap analysis — Color & visual-text SCs (1.4.1, 1.4.3, 1.4.5, 1.4.11)

28 aspects. Reasoned from aspect slug + WCAG 2.2 Understanding/Techniques + Trusted Tester v5.1.3 + EN 301 549 + the harness code (rubrics, `text-contrast-pixel`/`analyzeBackdrop`/`worstContrast` in `exp-runners.js`, `precomputeSignals` in `llm-adjudicator.js`, the oracle family map in `applicability-oracle.js`, `STATE_TRANSITIONS` in `act-page-collect.js`, and the LLM-callable CDP tools in `cdp-tools.js`). Held-out `eval/act-augmented/*/pages/` NOT opened.

## Standing architectural facts that drive most verdicts
- **State capture is SC-keyed and frozen.** `STATE_TRANSITIONS = {2.4.7:focus, 2.4.11:focus, 1.4.13:hover, 3.3.1:submit, 3.3.3:submit}`. **None of 1.4.1, 1.4.3, 1.4.5, 1.4.11 get a state pair** — they receive only a flat resting `element-crop`/`surrounding-region`. So any :hover/:focus/disabled/selected/error color or boundary is invisible unless it happens to be the resting state.
- **1.4.3 has a real deterministic runner** (`text-contrast-pixel`) that resolves effective fg through alpha/opacity cascade, the composited backdrop through the paint stack, and — via `analyzeBackdrop` — samples the *backdrop behind the actual glyph pixels* across the whole ink rect and takes the worst-case luminance percentile (`worstContrast`, p05/p95). This is a genuine per-letter / worst-region pixel-contrast capability for text.
- **1.4.11 has NO deterministic runner.** `applicability-oracle.js:162` literally states "No deterministic 1.4.11 runner exists ⇒ rubric-judged." (`focus-obscured-barrier` is 2.4.11, unrelated.) The non-text-contrast rubric judges a flat crop with no measured ratio and no per-boundary pixel sampling. The only quantitative help (`resolve_part_color`, `compute_contrast_ratio`, `compare_named_regions`) is **LLM-callable only, gated behind `opts.toolsEnabled`**, and the LLM lane is non-authoritative / often inert (per project memory).
- **1.4.1 is enumerated only for `link` + form-field** (`applicability-oracle.js:200`); status/chart/graphic color-coding surfaces are not minted as obligations. Color-blind/grayscale separation requires `render_with_overrides` (LLM-callable, tool-gated).
- **1.4.5 has NO deterministic image-of-text detector.** Only `svgLiveText` (clears vector text) and the LLM-callable `ocr_image_text`/`request_hi_res_crop` tools exist.

## Capability tags (clustered)

- **state-driven-color-capture** — aspects: 1.4.1 inline-links-color-only-no-other-cue, 1.4.1 error-validation-color-only, 1.4.1 ui-status-action-color-only-no-text-cue, 1.4.3 state-dependent-text-contrast, 1.4.11 state-indicator-contrast-adjacent-surface (5). Capture color/cue/contrast evidence in the NON-resting states a subject reaches (:hover, :focus, :visited, disabled, selected, checked/on, error/invalid) and re-measure, rather than only the flat resting crop. Requires adding 1.4.1/1.4.3/1.4.11 entries to `STATE_TRANSITIONS` with the appropriate state driver and re-running the contrast/color evidence per state.
- **nontext-contrast-runner** — aspects: 1.4.11 boundary-is-only-cue-context-flip, 1.4.11 graphical-object-required-for-understanding (2). A deterministic 1.4.11 runner that, like `text-contrast-pixel`, resolves a UI component's identifying boundary / a graphical object's meaning-bearing parts and computes the worst-case ≥3:1 separation against adjacent surfaces (today there is none; rubric-only on a flat crop).
- **nontext-effective-adjacent-resolution** — aspects: 1.4.11 adjacent-color-subsumption-and-comparison-surface (1). Resolve the true adjacent/comparison surface(s) for a NON-text part through the paint stack (the analogue of the 1.4.3 backdrop resolver, which is text-only) so the correct neighbor is compared along the whole boundary.
- **focus-indicator-contrast** — aspects: 1.4.11 f78-focus-indicator-occluded-but-present, 1.4.11 focus-indicator-geometry-inner-border-partly-outside (2). Capture the focused state and measure the focus indicator's NON-TEXT contrast against its real adjacent surfaces, geometry-aware (which indicator pixels fall on which surface) — distinct from the 2.4.7 focus-visible / 2.4.11 not-obscured lanes, which don't compute a 1.4.11 ratio.
- **nontext-exemption-signal** — aspects: 1.4.11 exemption-boundaries-inactive-hover-essential-symbolic (1). A deterministic inactive/essential/decorative signal for non-text components (the 1.4.11 analogue of 1.4.3's `inactiveText`) so the rubric isn't inferring exemption from pixels alone.
- **cvd-grayscale-render** — aspects: 1.4.1 color-coded-graphics-no-pattern-or-label (1). Provision a grayscale/CVD-simulated render (protanopia/deuteranopia/tritanopia/grayscale) as STANDING evidence for color-only graphics, instead of leaving it to the tool-gated, LLM-triggered `render_with_overrides`.
- **color-coded-graphic-enumeration** — aspects: 1.4.1 image-chart-alt-omits-color-encoded-fact (1). Enumerate charts/legends/color-keyed graphics for the `use-of-color` family (today the oracle mints 1.4.1 only for link/form-field) and hand the rubric region-color comparison (`compare_named_regions`-style) so it can judge a color-only encoding the text omits.
- **logotype-exemption-signal** — aspects: 1.4.3 logotype-brand-exemption-and-erosion, 1.4.5 false-logotype-branding-exemption (2). A signal/evidence that helps judge genuine wordmark/logotype status (and resist over-claiming the exemption) for both 1.4.3 text-in-image and 1.4.5 image-of-text.
- **ocr-image-text** — aspects: 1.4.5 in-addition-to-equivalent-live-text, 1.4.5 image-of-text-vs-live-text-core-detection (2). Provision OCR of the image text (and OCR-to-DOM-text comparison) as standing evidence rather than the tool-gated, LLM-triggered `ocr_image_text`/`request_hi_res_crop`, so small/stylized image text is read reliably and matched against any equivalent live text.
- **customizability-control-detection** — aspects: 1.4.5 customizability-exception-onpage-controls (1). Detect/surface the presence of on-page text-presentation-customization controls (font/size/color) so the rubric can apply the 1.4.5 customizability exception (page-wide evidence the element crop never sees).
- **picture-significant-content-signal** — aspects: 1.4.3 picture-with-significant-other-content-exemption (1). A signal distinguishing authored page-text-over-a-photo from incidental text within a larger meaningful picture, so the 1.4.3 "part of a picture with significant other content" exemption is applied correctly.

Demo note (not shown to users): This page fails WCAG 2.4.6 Test 5.B. Notice the contrast with the sibling fields: "Expiry (MM/YY)" and "Security code (3 digits)" both carry their format inline, but "Card number" does not — yet it has the strictest constraint (exactly 16 digits, no spaces). The label names the topic correctly and the field is properly associated and non-empty, so axe-core/WAVE/Lighthouse pass it. No automated tool reads the /^\d{16}$/ validator to know spaces are rejected, and none can judge that "Card number" alone fails to tell the user the accepted format while its own siblings show theirs.

# case-02 — Required fields flagged only by a red left-border on the input (no text cue at all)

## Scenario
A job-application form ("Warehouse Associate II" at Northgate Logistics), the kind generated by
an ATS. Required fields (full legal name, email, work-authorisation, forklift experience) are
flagged **only** by a 3px **red left-border on the `<input>`/`<select>` control itself**
(`.field--required` → `border-left:3px solid #d32f2f`). Optional fields keep a plain grey
border. There is **no asterisk, no "(required)", no icon, no `aria-required`** — and, unlike
case-01, there isn't even an instruction telling the user that the red edge *means* "required."
The mandatory/optional status is carried purely by the hue of one edge of the box.

## Attribute tuple
- **content-domain:** job board / applicant-tracking-system (ATS) application
- **UI-component/pattern:** multi-`<fieldset>` application form with grouped sections
- **host-language construct:** coloured `border-left` on `<input>`/`<select>` via a wrapper
  class `.field--required`; no `required`/`aria-required` attribute
- **locale/i18n:** en-US
- **failure-mechanism:** F81 — required field identified by a colour difference only (a coloured
  *border* on the control), with no non-colour cue and no explanatory legend

## Developer persona
A junior front-end dev themed an off-the-shelf ATS. The design system already had a
`.field--required` modifier that the designer had specced as "add a subtle red accent on the
left." The dev wired the class to the required fields and shipped it. He assumed the red accent
"reads as required to everyone," and the form was never tested in greyscale or with a
colour-blindness simulator, so the all-colour cue went unnoticed.

## Element / selector carrying the issue
`.field--required input`, `.field--required select`, `.field--required .upload` — the red
`border-left` is the sole required indicator. There is no text node, attribute, or icon
anywhere that distinguishes a required field from an optional one.

## Exact accessibility mechanism (what AT experiences, why it fails)
A screen-reader user hears "Full legal name, edit text" and "Preferred name, edit text" with no
difference — the red border is pure CSS, exposed in no accessible property, and there is no
`required`/`aria-required` to announce "required." A sighted colour-blind user sees boxes whose
left edges are red or grey but, with red-green deficiency, cannot reliably tell the red edge
from the grey one; even a user who *can* see the red has no legend telling them what it means.
Switching the page to greyscale (the canonical Trusted Tester detection technique) renders the
3px red edge and the grey edge as near-identical dark lines, erasing the only differentiator.
Required-vs-optional is therefore conveyed by colour alone with no visible alternative →
fails 1.4.1. (It would also fail 1.3.1/3.3.2 programmatically, but those are separate from the
visible-alternative requirement 1.4.1 imposes.)

## Expected ACT-style outcome
**failed**

## Why automated tools miss it
Each control has an associated `<label for>` and an accessible name; the text contrast passes;
the markup is well-formed. axe-core, WAVE and Lighthouse have **no rule** that reads a coloured
border on a form control, infers it is acting as a "required" indicator, and then checks for a
non-colour equivalent. A 3px coloured `border-left` is an utterly ordinary decorative style —
tools cannot know it carries semantic meaning here, let alone that the meaning ("this field is
required") is available through colour only and is never stated in text. Detecting this needs a
human to perceive the rendered controls and reason about what the red edge signifies.

## Citation
> **WCAG Techniques, F81 — "Failure of Success Criterion 1.4.1 due to identifying required or
> error fields using color differences only" (Tests › Procedure):**
> "For all required fields or error fields in the web page that are identified using color
> differences: 1. Check that an non-color way to identify the required field or error field is
> provided."

(Verbatim from `wcag-techniques/failures/F81.html`. The red `border-left` identifies required
fields by a colour difference; there is no non-colour way to identify them, so check #1 is false
and the failure applies.)

> **Trusted Tester v5.1.3, SC 1.4.1 — Identify Content:**
> "Displaying content in grayscale may help identify content that uses only color to convey
> information."

(Verbatim from `refs/trusted-tester/sc-1.4.1-use-of-color.md`. In greyscale the red and grey
control borders collapse to near-identical lines, exposing that colour is the only carrier of
required status.)

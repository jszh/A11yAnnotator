# SC 2.1.2 No Keyboard Trap — augmented test corpus

The ACT rules for SC 2.1.2 give essentially no automatable coverage: a keyboard trap is a *behavioral* property (focus cannot be moved away by standard keys), so it has no static signature an attribute scanner can read. The published ACT material stops at the plainly-detectable surface and leaves the SC's central failure technique and all of its conditional-pass carve-outs to human judgment. This corpus closes those gaps. It exercises the SC's only mapped failure technique, F10, on the cross-format / embedded-application boundary (iframe, object, embed, plug-in, shadow-DOM widgets) that the Intent calls the archetypal cause; it draws the legitimate-containment line for modals and popovers (intentional focus restriction is conformant *provided* the user can untrap and leave); it tests Esc and other platform "standard exit methods" as the untrap mechanism and the boundary where no advice is owed; it covers arrow-key / roving-tabindex composite-widget traps (menu, grid, listbox, radiogroup, tablist, slider) where Tab must still exit even when arrows are captured; it covers the G21 multi-element-region loop where the final Tab must exit; the required-input / sequential-gate exception (a section demanding interaction before focus progresses is *not* a failure); and the reachability and accuracy of documented custom-exit advice (G21: the user must actually be advised, and the advice must be reachable and correct).

Every page is authored for human-judgment review with verbatim WCAG / Trusted Tester citations, and several deliberately defeat naive automated trap heuristics (static tab-order walkers, OOPIF-isolated iframes, blur→setTimeout refocus loops) so that only a settled, keyboard-driven evaluation reaches the right verdict. Five of the seven aspects reach the full six valid human-judgment pages. Two aspects fall to five valid pages and are therefore at the threshold rather than above it: **input-gate-required-interaction-exception** has one dropped page (case-06: the file at that path is a different, conformant page than the prompt's claimed pointer-drag slider trap, so its expected-outcome label is wrong for the actual artifact), and **documented-exit-reachability-and-accuracy-beyond-ctrlm** has one needs-fix page (case-05: a prompt/metadata mismatch makes the recorded "passed" label wrong, though the file itself is a sound "failed" case). All other pages are valid and recommended to keep.

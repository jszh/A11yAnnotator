# case-04 — Dev-console key table: row-action icons named with PUA codepoints

## Scenario
A developer console ("Beacon") lists API keys in a data table. Each row has two
icon-only action links: a pencil (edit the key) and a trash can (revoke the key). The
icons come from a custom icon set whose build pipeline assigned every glyph a Unicode
Private Use Area codepoint (U+E801 for the pencil, U+E803 for the trash) and then
auto-generated the `aria-label` as the *literal PUA character itself* rather than a
word. So each action link's accessible name is a single private-use character —
non-empty (c487ae/F89 pass) but semantically meaningless, since PUA codepoints carry no
assigned Unicode meaning and screen readers cannot announce them usefully.

## Attribute tuple
- **content-domain:** developer docs / API reference console
- **UI-component/pattern:** data-table row actions (edit / delete icon links)
- **host-language construct:** `<a aria-label=""><svg aria-hidden="true">…</svg></a>` (PUA char as the name)
- **locale/i18n:** en-US, but the name is an unassigned Private Use codepoint
- **failure-mechanism:** icon-font build emits the glyph's PUA codepoint as the accessible name — present, non-empty, conveys nothing

## Developer persona
A team adopted an in-house icon font generated by a CLI (fantasticon / icomoon-style)
that maps each SVG to a Private Use codepoint and can scaffold "labels." A backend
engineer wiring the table grabbed the tool's generated label map, which for these glyphs
contained the raw codepoint string, and passed it straight into `aria-label`. The lint
rule "interactive element must have a name" went green because the codepoint *is* a
non-empty string. Visually the pencil and trash render fine, so it shipped; nobody tried
the table with a screen reader.

## Element / selector carrying the issue
`table .actions a[href$="/edit"]` (name = U+E801, a pencil) and
`table .actions a[href$="/revoke"]` (name = U+E803, a trash can) — six links across
three rows, each named by an unassigned Private Use Area character.

## Exact accessibility mechanism
Each `<a>` is in the accessibility tree with role `link` and a non-empty accessible name
consisting of one PUA character (the inner SVG is `aria-hidden="true"`). Because U+E801
/ U+E803 are unassigned outside this private font, a screen reader has no glyph name to
read: depending on the AT it announces nothing, says "private use area E801," or reads a
fallback symbol — none of which conveys "Edit key" or "Revoke key." The name-presence
floor is satisfied, but the user cannot determine the link's purpose, and for the trash
icon the consequence is destructive (revoking a key) with no spoken warning. 2.4.4 fails.

## Expected ACT-style outcome
**failed** (SC 2.4.4 Link Purpose (In Context)). c487ae *passes* (the PUA character is a
non-empty accessible name); F89 inapplicable (the links are named, not empty).

## Why automated tools miss it
The accname computation returns a non-empty string for each link (one PUA character), so
axe-core / WAVE / Lighthouse report discernible text and raise no violation; the
empty-name path (F89) never triggers. No automated tool resolves the PUA codepoint back
to the pencil/trash glyph it was minted for, renders that glyph, and judges that the
announced name fails to convey "edit" or "revoke" — the codepoint-to-meaning mapping
exists only inside the private font and the visible rendering, so detection is visual and
human-only.

## Citation
> **Reference:** WCAG Technique F89 — "Failure of Success Criteria 2.4.4, 2.4.9 and
> 4.1.2 due to not providing an accessible name for an image which is the only content
> in a link" (`wcag-techniques/failures/F89.html`)
>
> **Quote (verbatim):** "This failure condition occurs when a link contains only
> non-text content, such as an image, and that link cannot be identified by an
> accessible name." *(Here the link IS technically named — a PUA character — so F89's
> empty-name failure does not apply, yet the name identifies nothing, so 2.4.4 still
> fails.)*
>
> **Reference:** WCAG Technique H30 — "Providing link text that describes the purpose of
> a link for anchor elements" (`wcag-techniques/html/H30.html`)
>
> **Quote (verbatim):** "When an image is the only content of a link, the text
> alternative for the image describes the unique function of the link."

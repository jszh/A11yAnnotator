Demo note (not shown to users): This page fails WCAG 2.4.6 Test 5.B. The password field's purpose is clear, but its applicable data requirements (minimum 12 characters, at least one symbol) are not communicated by the label or its instruction — the only on-screen guidance, "Choose something memorable", is friendly but does not state the rules, and the rules surface only in the post-submit error. Automated tools pass it: the label is associated and non-empty and the help text is present, so axe-core/WAVE/Lighthouse see a well-labelled field. No tool reads the validator to learn the 12-char/symbol rule, and none can judge that the visible instruction fails to state the requirement while the error does — "error-as-format", which TT 5.B disallows.

Pagination

All top-level API resources support bulk fetches through "list" endpoints. The Orbit API uses cursor-based pagination: each list response carries a cursor that you pass back to retrieve the next page. Cursor pagination is stable under concurrent writes, which offset pagination is not.

Overview

List endpoints return a data array and a has_more boolean. When has_more is true, take the id of the last item and pass it as starting_after on your next request.

Cursor parameters

ParameterTypeDescription
limitintegerPage size, 1–100. Default 10.
starting_afterstringObject ID; returns items after this one.
ending_beforestringObject ID; returns items before this one.

Response shape

Every paginated response is wrapped in a list object so you can detect the end of the collection without a second call.

// GET /v3/charges?limit=2
{
  "object": "list",
  "has_more": true,
  "data": [ { "id": "ch_3Mx1" }, { "id": "ch_3Mx2" } ]
}

Code examples

Loop until has_more is false, advancing the cursor each iteration:

let after = null;
do {
  const page = await orbit.charges.list({ limit: 100, starting_after: after });
  process(page.data);
  after = page.data.at(-1)?.id;
} while (page.has_more);

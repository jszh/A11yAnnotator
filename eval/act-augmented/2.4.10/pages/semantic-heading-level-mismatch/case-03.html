Webhooks API — Endpoints

The Webhooks API lets your integration register HTTPS callbacks and stop receiving them later. There are two endpoints in this resource. Both act on the same /v2/webhooks collection and require a secret-key bearer token; neither is a sub-operation of the other.

POST Create a webhook

Registers a new callback URL. Returns the created webhook object, including the generated id and the signing_secret you use to verify deliveries. This is one of the two operations the resource exposes.

POST /v2/webhooks
Authorization: Bearer sk_live_***
Content-Type: application/json

{ "url": "https://app.example.com/hooks/parcelo",
  "events": ["shipment.delivered", "shipment.delayed"] }
FieldTypeDescription
urlstringHTTPS endpoint to call.
eventsarrayEvent types to subscribe to.

DELETE Delete a webhook

Permanently removes a webhook so it stops receiving deliveries. This is the second of the resource's two equal endpoints — it stands on its own and is in no way nested beneath "Create a webhook". A 204 No Content response confirms removal.

DELETE /v2/webhooks/{webhook_id}
Authorization: Bearer sk_live_***
ParameterInDescription
webhook_idpathID of the webhook to delete.

Verifying deliveries

Regardless of which endpoint you called, every delivery Parcelo sends is signed with the webhook's signing_secret. Compute the HMAC-SHA256 of the raw request body and compare it to the Parcelo-Signature header.

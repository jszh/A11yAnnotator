What a pipeline is

A pipeline is a declarative description of how raw events flow from a source, through one or more transforms, into a destination table. Pipelines are versioned, replayable, and run continuously: when new events arrive at the source, DriftDB applies your transforms and writes the results downstream without you re-running anything by hand.

Tip: Pipelines are idempotent. Re-deploying the same definition will not duplicate already-processed events, so it is safe to redeploy often while you are iterating.

Create your first pipeline

Define a pipeline in a single file. The example below reads from a Kafka topic, keeps only completed orders, and writes a rolling daily total into a results table. Notice that even a very long connection string wraps cleanly rather than forcing the page to scroll sideways: 

source kafka {
  brokers = "broker-01.use1.prod.internal:9092,broker-02.use1.prod.internal:9092,broker-03.use1.prod.internal:9092"
  topic   = "orders.v3"
}

transform filter_completed {
  keep when status == "COMPLETED"
}

destination table daily_totals {
  rollup = sum(amount) by date_trunc('day', ordered_at)
}

Deploy it with driftdb pipeline deploy ./orders.pipeline. Within a few seconds the pipeline shows as running, and the destination table begins to fill as events are processed.

Payments API · v3

Charges & Refunds endpoints

REST operations for creating, retrieving and reversing charges. Select an operation to jump to its full reference.

Operations

  • POST/v3/charges Create a charge against a saved payment method.
  • GET/v3/charges/{id} Retrieve a single charge by its identifier.
  • POST/v3/charges/{id}/refunds Issue a full or partial refund for a charge.
  • GET/v3/charges List charges with cursor-based pagination.
  • DELETE/v3/charges/{id} Void an uncaptured charge before settlement.

All endpoints require a bearer token in the Authorization header and return JSON.

There is a genuine author-supplied focus style (.endpoints a:focus { outline: 2px solid #000; outline-offset: 1px }), so no scanner can flag a "removed" indicator, outline:none never appears, and a single-chip focused-vs-unfocused pixel diff is non-zero (a 2px line is painted just outside the box). axe-core, WAVE and Lighthouse therefore pass 2.4.7. Yet every endpoint chip already wears a permanent border: 4px solid #000, and the focus ring is the exact same black and thinner than that border — so the ring is absorbed into the chip's own thick black frame and a keyboard user cannot tell which of the five endpoints currently holds focus. Concluding that a 2px black ring against a 4px black border is not distinguishing requires a human to read the colours in context and weigh perceptual contrast, not the edge-pixel count an automated rule performs (F78 mode 3).

Why automated checkers miss this: The markup is valid APG-shaped menu code — role="menu", role="menuitem", a roving tabindex (one item tabindex="0", the rest -1), an accessible name, and a correct aria-expanded toggle. axe/WAVE/Lighthouse see a structurally correct menu and a valid focus order. The trap is purely behavioural: the keydown handler calls preventDefault() on Tab and Shift+Tab while the menu is open, so once focus is in the menu it can move between items with the arrow keys but can never leave to the promo field or the checkout button. Detecting it requires actually pressing Tab inside the open menu and observing that document.activeElement never advances — static scanners never press keys.
